# BASIC-156 UI-16 변경 및 검증 기록

## 적용 범위와 보존 동작

- 공통 SharedScreenFrame·ScreenPeriodBar·PeriodStatus와 기존 React Router 이동을 재사용했다. 제목·즐겨찾기·UI-16·메뉴 경로를 별도 헤더로 대체하지 않았다.
- 제목 오른쪽에는 데스크톱 엑셀 버튼만 두고, 조회 범위·단위·기준일·마감월·잠정 상태는 조회월 옆에 배치했다. 과거월에서는 재무 지표와 오늘 기준 운영 정보를 구분하고 할 일별 실제 기준을 표시한다.
- 상단은 추이/재무 지표와 운영 지표/확인할 일, 중단은 인력 수급과 마감/경보, 하단은 실적/파이프라인/자금으로 구성했다. 상·중단 60:40, 하단 균등 열, 바깥 카드 간격 16px, 모바일 단일 열과 재무 지표 2+1 배치를 적용했다.
- 추이는 최근 3개월을 기본으로 하며 전체 기간과 상세 숫자표를 전환한다. 차트·툴팁·표는 화면 금액 단위를 사용한다. 연도가 바뀌는 1·2월은 필요한 경우 기존 대시보드 API로 전년도 12월을 추가 조회하여 원본 행을 연결한다. 운영 시작 이전은 조회하거나 임의 생성하지 않는다.
- 자금 차트에는 API의 월말 잔액과 최소 자금을 실선/점선으로 표시한다. 모바일에서 마지막 월이 잘리지 않도록 축 끝 글자를 안쪽으로 정렬했다. 대시보드 차트 글자는 테마의 본문 보조 색상을 사용한다.
- 할 일은 건수가 있는 유형을 급한 순서로 안정 정렬하고 최대 5개만 요약한다. 전체/급함 배지는 유형 수이며, 6개 이상이면 전체 모달을 연다. 모달은 기존 Dialog의 내부 스크롤·Escape·초점 복귀를 사용한다. 카드와 모달은 같은 업무 이동 함수를 호출한다.
- 프로젝트·자금 행의 상태 배지는 88×24px, 12px 글자로 고정했다. 마감 진행은 API의 실제 전체 점검 수만큼 구간을 만들고 통과한 구간만 채운다.
- 최초/다른 월 조회는 장식용 반응형 스켈레톤과 상태 문구를 표시한다. 같은 월 갱신은 기존 결과를 유지한다. 오류·재시도·권한 상실 시 데이터 제거·엑셀 비활성화는 기존 흐름을 유지한다.
- 스켈레톤은 공통 진입 애니메이션에서 제외하여 자체의 느린 밝기 변화가 덮이지 않게 했다. 모션 줄이기에서는 스켈레톤과 회전 표시가 정적이다.
- API envelope/status·권한·업무 계산/반올림·목적 화면/월/탭/필터·서버 엑셀 출력·인증 정책은 변경하지 않았다. 백엔드·DB 스키마·컨테이너 설정·초기 로그인 안내 파일도 변경하지 않았다.

## 실행 환경과 방법

- 현재 worktree의 production frontend build를 Chromium으로 열었다. e2e/scripts/test-built-ui.mjs는 테스트 실행 동안만 빌드 파일을 제공하고 실제 검증 API를 프록시한 뒤 종료한다. 개발 서버/워처를 상시 실행하지 않는다.
- 실제 로그인·메뉴·권한·조회·다운로드 API를 사용했다. API 데이터 대신 만들어 낸 응답을 사용하지 않았다. 지연은 실제 요청을 잠시 보류한 뒤 통과시키고, 실패는 네트워크 요청 중단으로 재현했다.
- 검증 API와 계정은 실행 환경의 SICOST_VERIFY_API·SICOST_VERIFY_USER·SICOST_VERIFY_PASSWORD에서 사용했다. 값·쿠키·토큰은 이 문서와 캡처에 기록하지 않았다.
- 기존 비밀번호 변경 권장 안내는 정상적인 ‘나중에’ 버튼으로 처리했다. 세션/권한 재조회 뒤 재표시되는 안내 때문에 클릭이 가려지는 테스트 경쟁 조건을 locator handler로 처리했으며, 인증·권한을 우회하거나 안내 DOM을 강제로 숨기지 않았다.
- 환경의 Node는 v22.21.1, npm은 10.9.4였다. 저장소의 Node 20.x engines 경고가 있었지만 의존성 설치·타입 검사·빌드는 성공했다. 패키지/lockfile 버전은 변경하지 않았다.

## 실제 브라우저 조작과 관찰

### 배치·헤더·표·배지

- 최종 통과 실행에서 2026-02를 1440·1700·1280·390px로 각각 열었다. 앞선 통과 실행에서는 2026-01·2026-10도 같은 폭으로 확인했다.
- 1440·1700px에서 상·중단의 좌우 열 경계와 하단선, 60:40 비율, 하단 세 카드의 같은 폭/높이를 DOM 좌표로 대조했다. 통과했다.
- 1280·390px에서 대시보드/문서 전체 가로 넘침이 없음을 확인했다. 실적표 내부를 오른쪽 끝으로 스크롤하여 마지막 열까지 확인했다. 390px에서는 재무 지표 첫 줄 2개와 누계 전폭 배치가 확인됐다.
- 거래처·영업 파트(UI-15) 및 기존 인접 업무 화면(UI-18)을 번갈아 열어 공통 제목의 왼쪽 좌표와 높이를 대조했다. 통과했다.
- 실제 자금 ‘예측’ 배지는 각 폭에서 88×24px, 글자 12px이었다. 모바일 캡처에서도 오른쪽 정렬과 월별 행의 금액/최소 자금을 읽을 수 있었다.

### 조회·차트·테마·다운로드

- 현재월 2026-11과 과거월 2026-10을 선택하고 최근 3개월/전체 기간을 전환했다. 각 범위의 월별 행 수와 매출/원가/목표 표시값을 실제 API 값과 대조했고, 선택월이 유지됐다. 통과했다.
- 자금 차트의 실선/점선과 2026-11·2026-12·2027-01의 월별 잔액/최소 자금 행을 대조했다. 390px에서 마지막 2027-01 글자 잘림을 발견해 수정하고 같은 조건으로 재확인했다. 통과했다.
- 밝은/어두운 테마에서 실제 마감 점검 전체 수와 통과 수를 표시 구간 수와 대조했다. 통과했다. 실데이터는 6/6으로, 남은 구간이 있는 상태의 시각 검증은 아래 미검증 항목으로 남겼다.
- 어두운 테마 캡처에서 인력 수급 차트 글자의 낮은 대비를 발견해 대시보드 차트만 테마 색상으로 보정했다. 보정 후 같은 테마 캡처에서 범례·월·축 단위의 가독성을 재확인했다.
- 두 조회월에서 조회 완료 후 실제 엑셀 다운로드를 실행했다. 브라우저 다운로드 실패가 없고 xlsx 파일로 전달됐다. 통과했다.

### 업무 이동

- 실제로 존재하는 법인세 납부 확인 행을 눌러 UI-10의 법인세 영역과 해당 기준월이 적용되는 것을 확인했다. 통과했다.
- 자금 월별 행을 각각 눌러 UI-21 목적지, 전달 월, 기존 ‘대시보드 요청월’ 안내를 확인했다. 조회 가능 연도 밖의 안내를 임의로 바꾸지 않았다. 통과했다.
- 요약 지표 5개와 월 마감·파이프라인 업무 버튼의 기존 목적 화면 이동을 확인했다. 통과했다.
- 프로젝트 경보는 실데이터가 없어 해당 행 이동은 수행하지 못했다. 코드의 기존 projectId/month 전달과 단위 회귀 테스트는 유지했다.

### 로딩·갱신·오류

- 1440px에서 2026-10→2026-01, 390px에서 2026-01→2026-02를 조회하며 실제 API 요청을 보류했다. 최초 진입과 월 변경 모두 스켈레톤/상태 문구가 보이고, 응답 후 선택월 데이터로 바뀌었다. 통과했다.
- 같은 월의 갱신 이벤트를 발생시키고 요청을 보류했다. 현재 카드의 텍스트가 유지되고 스켈레톤 대신 ‘갱신 중…’이 표시됐다. 통과했다.
- 모션 줄이기에서는 스켈레톤의 computed animationName이 none이었다. 스켈레톤은 aria-hidden=true이고 초점 가능한 컨트롤이 없었다. 통과했다.
- 이미 준비된 기간 선택기에서 다른 월을 선택하며 네트워크 실패를 발생시켰다. 오류/재시도와 비활성 엑셀을 확인하고, 요청 차단을 해제한 뒤 재시도를 눌러 실제 데이터가 돌아왔다. 통과했다.

### 인쇄

- 1440px, 2026-01·2026-02에서 Chromium 인쇄 매체와 실제 PDF 생성을 실행했다. PDF 텍스트를 추출하여 요약 지표 5개가 같은 출력 페이지에 있고 각 표시값·단위·기준이 화면과 일치함을 대조했다. 통과했다.
- 인쇄 전후 추가 대시보드 조회는 0건이고 화면의 표시값도 유지됐다.
- OS/브라우저 고유 인쇄 미리보기 대화상자를 사람이 직접 조작한 검증은 아니다. 아래 제한을 참고한다.

## 미검증 항목과 사유

다음 항목은 구현됐지만 실제 브라우저 합격을 선언하지 않는다.

1. 0·5·6·12유형 및 급함 4유형의 실제 데이터별 모달 흐름: 제공 API 결과가 전체 1유형/급함 1유형이었다. 0·5·6·12유형의 요약 수·정렬·전체 목록 수·Escape/닫기·초점 복귀와 선택월 청구 누락 이동은 컴포넌트 테스트에서 통과했다. 실제 12유형 모달의 내부 스크롤, 본문 높이/스크롤 불변과 모든 모달 목적지는 해당 업무 데이터가 있는 환경에서 재검증해야 한다.
2. 긴 프로젝트명/경고 사유, 매우 긴 금액, 예산 초과·예산 주의·저마진, 자금 부족·미확인 배지의 상태별 실데이터 검증: 실제 프로젝트 경보는 0건이고 자금 행은 예측 상태였다. 존재하는 예측 배지의 실제 크기/정렬은 확인했지만 나머지 상태의 브라우저 결과를 대신 주장하지 않는다.
3. 마감 잔여 구간의 두 테마 시각 비교: 실제 조회 결과는 6/6이었다. 3/6 구간 생성은 컴포넌트 테스트에서 검증했으며 남은 구간은 테마 divider 색상/opacity 0.6으로 구현했다. 잔여 점검이 있는 실제 조회 결과로 시각 비교가 필요하다.
4. 매출 추이의 전년도 연결 실데이터: 현재월은 2026-11, 운영 시작월은 2026-01이어서 전년도 운영 자료가 없었다. 2027-01·2027-02의 추가 조회·원본 행 연결·선택월 보존은 단위 테스트에서 통과했다. 실제 연도 경계의 매출 추이는 추가 데이터가 있는 환경에서 확인해야 한다. 자금/수급의 연도 경계 표기는 실제 화면에서 확인했다.
5. 브라우저 고유 인쇄 미리보기 UI: 제공 환경은 headless Chromium이다. 인쇄 매체/PDF 실제 생성 및 내용 대조는 통과했으나, 사람이 네이티브 인쇄 미리보기에서 읽는 확인은 별도로 필요하다.

UI 검증을 위해 가짜 API 응답이나 임의 업무 데이터를 주입하거나 운영 DB를 시드하지 않았다. 이 제한을 이유로 구현 범위를 삭제하지도 않았다.

## 캡처
